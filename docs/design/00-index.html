Behaviour notes for screens without room for them

Chat

  • Text streams as a preview; the final answer event replaces it with the checked, renumbered answer (D24). The badge says citations are checked when complete.
  • A follow-up shows what was searched (“Searched as”) when the question was rewritten.
  • Citation chips scroll the sources panel to the card and outline it; the supporting sentence is highlighted.
  • Answers built from a newer and an older document carry the “Newer document preferred” badge; the older source is marked Superseded.
  • “Turn into eval question” opens a pre-filled form that appends to eval/candidates.jsonl; it never edits the eval set.
  • “Why this answer” is shown to admins only.
  • The retrieval details table is collapsed by default and keyboard-expandable.

Chat · agent mode

  • Each step is collapsible; the latest is open. Parallel tool calls are one step.
  • The approval card is the same component as the draft on the Tickets screen. Title, body and priority are editable before approval.
  • Reject asks for an optional reason and ends the run; Approve resumes it. Only the requesting user (or an admin) can approve.
  • The footer line shows the step and token budgets, so a long run is visibly bounded.
  • Evidence numbers are global to the run; the final answer may cite only these (evidence tracking).

Library · document drawer

  • Opens from a row click or Enter; the URL becomes /library/:documentId. Focus moves to the close button, is trapped in the drawer, and returns to the row on close.
  • Editable only by the owner or admin; others see the same fields read-only, with no Save or Delete.
  • Access checkboxes list only the editor's own groups. Removing the editor's last group warns that they will lose access.
  • Save with no changes is disabled. Unsaved changes prompt before closing.

Library · delete

  • Focus starts on Cancel, not Delete. Escape cancels.
  • Bulk deletes of more than 10 documents ask the user to type the number of documents to confirm.
  • After deleting, a toast confirms it and the table refreshes; no undo, because chunks are gone from every index.
  • An old answer citing a deleted document shows its chip dashed and greyed, with “Source deleted” in the source card (see 18-states).

Upload

  • Type, size and an empty file are checked in the browser using GET /api/config; the server checks again.
  • Settings apply to the whole batch. Access defaults to “Only me”; only the uploader's own groups are offered.
  • Uploading closes the dialog and shows a toast linking to Jobs; rows appear in the library with a progress status.
  • A file identical to one the user can already see becomes a no-op with “Already in your library”. A file that matches a document the user can't see is indexed as a new document: nothing reveals the other one.

Across every screen

  • Routes as in M3b; filters and selections in search params.
  • Lab and Admin are hidden for non-admins, and their routes return 404 from the server.
  • The user switcher in the header changes the X-User header (development only) and reloads data.
  • Focus is trapped in drawers and dialogs and returns to the trigger; every action works by keyboard; / focuses search, n starts a new chat.
  • Minimum target size 36 px, 44 px for primary actions. Light theme only, as in the NovaBridge design.
  • Model output is rendered as text, never HTML.
